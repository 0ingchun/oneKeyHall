# oneKeyHall 串口协议

> 当前应用 V2.6.1，配置 V06，137 字节，15 条命令。统一发布 `firmware/build/onekeyhall-ch552-24mhz.hex`，默认支持手动 ISP（能力 0xFF）。


USB VID/PID 沿用 `1209:C550`；网页打开 CDC 时使用 57600 波特率并置 DTR。本版本已移除原驱动的 1200 波特率 BootLoader 触发逻辑；旧版仍可能触发，不应尝试。

请求格式为十进制 `{key:value}`，key/value 均最多 3 位。接收器支持跨 USB 包分片和连续命令，遇到畸形输入取消当前帧，遇到新的 `{` 重新同步。一次 loop 最多读 64 字节。

普通写入的应答是 `[1000,key,status]\n`，命令应答为 `[1000,command,status]\n`。每次请求等待相应应答后再继续。不要用固定延时假设写入已成功。

## 命令（key = 999）

| value | 含义 | 响应 |
| --- | --- | --- |
| 0 | 校验、保存 Data Flash、回读确认、结束设置并等待松开 | ACK |
| 1 | 读取 137 字节当前配置（V06；V04/V05 长度相同）；旧 V03/V02 为 124/100 字节，计数以运行值替换 | 配置数组 + 换行 |
| 2 | 更新常亮 RGB | ACK |
| 3 | 获取一次实时状态；网页最多约 10 次/秒 | 状态数组 |
| 4 | 查询能力位，bit 0 = 手动 ISP；bit 1 = RT 极值；bit 2 = 模拟行程线性模式；bit 3 = 名称/双击间隔；bit 4 = 设备内线性 HID 输出；bit 5 = ROM 身份；bit 6 = 行程灯效；bit 7 = 双击反向/方向状态/线性计数 | 当前 `[1002,255]\n`；较早 v2 返回 `[1000,4,1]\n`，视为无此能力 |
| 5 | 只读查询应用固件版本 | `[1003,major,minor,patch,1]\n`；当前 `[1003,2,6,1,1]`；最后一项固定为 1，表示支持 ISP；旧固件可能返回 `[1000,5,1]` |
| 6 | 只读查询 BootLoader 和 UID，能力 bit 5 | `[1004,bcdLow,bcdHigh,uid0,uid1,uid2,uid3,uid4]\n`；无法识别版本为 0,0，旧固件拒绝 |
| 10 | 开始设置，备份当前配置，释放按键并暂停输出；重复调用不覆盖备份 | ACK |
| 11 | 采集松开端点，需先进入设置 | 32 次采样完成后 ACK |
| 12 | 采集压到底端点，需已成功采集松开端点 | 32 次采样完成后 ACK |
| 13 | 校验并应用 RAM 配置、结束设置并等待松开 | ACK |
| 14 | 取消设置，恢复备份，释放按键并等待松开 | ACK |
| 15 | V2.6.1 起恢复出厂设置，无需设置会话；采样中拒绝。清除配置、校准、名称和累计次数，立即写入并校验 DataFlash | 成功 `[1000,15,0]`；采样中 `[1000,15,1]`；存储失败 `[1000,15,5]` |
| 16 | 释放当前输出并等待顶部重新就绪；音量预设重新归零同步，不保存 Flash | ACK |
| 99 | 当前默认固件关灯、应答后等待 300 ms，再执行 ISP 交接 | 当前 `[1000,99,0]`；拒绝 `[1000,99,1]` |

0/13 只允许设置会话中调用，采集中不可提交。普通字节写入仅在设置会话中且不在采集时允许，不能直接写入校准标志和端点。11/12 采集更新校准；15 恢复出厂时清除校准。采集失败保留原校准；松开端点暂存在 RAM，成功获取第二端点后才一起更新配置。

网页停止修改有效参数约 400 ms 后执行 10 → 差异写入 → 13；“保存配置”使用 0 代替 13。网页成功采集底部后自动发送 13 应用校准。命令 15 在确认后单独执行并立即持久化，不受默认“只应用、不保存”的规则限制。

应用版本由 `firmware/src/FirmwareVersion.h` 定义，与 config[0]=6 的配置格式及 ROM BootLoader 版本分开。网页从命令 5 只显示应用版本号；无版本接口的旧固件显示“未上报”。BootLoader 由命令 6 实际读取，不固定为 2.50。升级 V2.6.0 → V2.6.1 不改变配置格式或清空参数。

### 历史版本兼容说明

历史 2.2.0 新增能力 bit 2（值 4）：支持 config[4]=3 的线性模式。版本应答为 `[1003,2,2,0,1]`。线性模式继续采样并提供既有行程状态，不发送 KEY1/KEY2，也不增加按键释放计数。2.2.0 配置仍为 100 字节，不扩展 EEPROM；0/1/2 的工作模式含义不变。当时网页检测 bit 2 才允许应用模式 3。线性控制运行时，状态查询完成后约 25 ms 发下一次，其余时间约 100 ms。预设映射与 Windows 输出放在上位机，该伴随程序路径在 2.4.0 被设备 HID 输出替代。

历史 2.3.0 新增能力 bit 3（值 8）：名称和双击间隔；版本 `[1003,2,3,0,1]`，配置格式升级为 3，长度 124。网页同时兼容旧 100 字节 V02，但只在 V03 上开放名称和双击间隔编辑。

历史 2.4.0 新增能力 bit 4（值 16），必须同时满足配置 V04 和此能力位，网页才允许应用设备线性模式。预设参数为 config[124..136]；版本应答 `[1003,2,4,0,1]`。网页不再调用 Windows 伴随程序，状态查询约 100 ms，设备 HID 输出不依赖查询。

2.1.0 接受命令 99 后发送全黑 RGB 数据，再 ACK、等待 300 ms 并执行已验证的 TMOD 清理跳转。等待期间停止灯效更新；不更改亮度/颜色配置，不写 DataFlash。若 BootLoader 超时返回应用，应用会按原参数恢复灯效。

## 实时状态与错误码

状态数组为：

```text
[1001,raw,filtered,position,pressed,calibrated,armed,settingsOpen,span,fault,extreme,cycle,reversed]
```

- `position`：0–100 归一化 ADC 信号；无校准时为 0，网页应显示未校准。
- `pressed`：磁轴判定且输出未暂停。双击或文本模式下不等于具体 HID 报告中的持有键。
- `armed`：是否已在顶部死区完成释放确认。
- `fault`：本次原始 ADC ≤1 或 ≥254；立即释放，回到顶部才重新允许触发。无法检测所有断线形式，例如悬空且恰好停在有效电压范围。

- `extreme`：RT 当前阶段跟踪的极值，按下时为峰值，释放时为谷值，单位为相对行程百分比。
- `cycle`：已首次触发且尚未回到顶部死区的 RT 周期标志。只在 RT 开启、已就绪、未暂停且无故障时用于动态阈值。
- `reversed`：相对于当前已应用预设的临时反向状态 0/1，不是持久化的反向开关。

网页兼容旧版 10 项状态；旧版只显示以当前行程为基准的 RT 距离参考。12/13 项状态用于显示实际下一次转换阈值：按下时 `max(top, extreme - 有效抬起距离)`，释放时 `extreme + 有效重新按下距离`，仍需满足固件连续采样确认。另一条线仅作距离参考；超出 100% 的再次按下阈值显示“超出行程”，需进一步抬起或顶部复位。未应用参数只作预览。RT 状态扩展本身不改变配置布局；2.4.0 的配置格式变更另见下文。

状态码：0 成功；1 操作顺序或写入目标错误；2 参数不合法；3 采样抖动超过 4 计数/接近电源轨；4 校准跨度小于 16；5 Data Flash 写后回读失败。

### DataFlash 打包布局

RAM/串口仍用上述 137 字节布局。Flash 仅 128 字节，物理地址 0–126 为负载，127 为 CRC-8（多项式 0x07、初值 0，覆盖 127 字节）。先标记地址 0 为 255，写其余负载和 CRC，最后提交格式 6。写后按打包值逐字节回读，失败报状态 5。格式/CRC 错误时使用未校准默认配置。

| Flash 地址 | 来源 |
| --- | --- |
| 0 | config[0] = 6 |
| 1–2 | config[2..3] 计数 |
| 3 | config[4] 位 0–1；config[17] 位 2–3；config[53] 位 4–5；config[14] 低 2 位存位 6–7 |
| 4 | config[5] 双击间隔 |
| 5 | config[6] 名称长度存低 4 位，config[14] 的 bit 2 存 bit 4 |
| 6–11 | config[10], [11], [12], [13], [15], [16] |
| 12–46 | config[18..52] |
| 47–81 | config[54..88] |
| 82 | config[89] 位 0；config[94] 位 1；config[97] 位 2–3；config[98] - 1 位 4–7 |
| 83–89 | config[90], [91], [92], [93], [95], [96], [99] |
| 90–113 | config[100..123] USB 名称 |
| 114–126 | config[124..136] 线性参数 |
| 127 | CRC-8 |

config[1] 产品类型和保留字节 [7..9] 不存储，V04/V05/V06 启动时为 0。V02 先校验原 100 字节和地址 100 的 CRC；V03 校验原 124 字节和地址 124 的 CRC。保留校准、计数、按键及灯效；V02 初始化 200 ms 双击和空名称，V03 保留名称/双击。两种旧格式均初始化线性预设，若旧模式为 3 则改成 0（KEY1），避免升级自动输出。V01 保留原 89 字节并初始化磁轴参数、名称、双击与线性参数。迁移不立即写 Flash。V04 升 V05 保留全部字段（包括设备内线性预设），无需清空 DataFlash。V05 保存后旧固件不能读取，回刷须重新配置。


名称仅在启动完成配置校验后复制到 USB 字符串缓冲区，再启动 USB；本次连接中保持不变。应用只改 RAM 配置名称；保存后拔插才更新 USB 产品（索引 2）和 CDC 接口（索引 4）字符串。当前默认产品/串口字符串为 oneKeyHall 加 10 位大写十六进制 UID，自定义名称优先；VID/PID 和 USB serial-string 不变。当前 HID 提供键盘、鼠标、媒体键和触屏报告；V2.6.1 的 USB bcdDevice 为 0x0261，不代表 BootLoader 版本。双击窗口从第一次按下计时，第二次按下必须严格早于窗口末尾；等于或超过末尾先派发单击，随后按新按下处理。

RT 第一次按下需越过固定触发点；之后记录按下阶段峰值，回退达到抬起距离则释放，记录释放阶段谷值，再前进达到重新按下距离则按下。顶部死区清除 RT 周期。实际距离取设置百分比与 `ceil(200 / ADC跨度)` 的较大值。

串口超时、断流或底层传输写入失败时，网页关闭连接，不在同一失同步流上重试，避免迟到 ACK 被误认为新请求成功。参数校验错误或固件返回拒绝 ACK 不等于串口断流：普通设置提交失败会尝试命令 14 回退未提交会话并显示错误；恢复出厂请求失败则关闭连接，由用户重新连接确认状态。

## 历史记录：软件 ISP 撤回及候选版本

2026-11-16 收到点击下载按钮后电脑异常关闭的反馈。根因未确定前，命令 99 固定拒绝且不改变 HID、设置会话或 USB 状态；能力 bit 0 清零，CDC 1200 波特率触发也已移除。host 后续已按用户要求恢复下载入口：根据能力 bit 0 启用按钮，用户确认后发出命令 99；撤回版固件继续拒绝。配置版本和布局不变。

恢复网页不改变已刷入设备的固件。复现取证步骤见 [取证说明](REPRO_CAPTURE.md)。详见 [排查记录](ISP_INCIDENT.md)。

### 早期 ISP 交接排查（2.1.0 之前）

排查期间恢复手动命令 99：成功应答、释放按键并暂停输出，等待 300 ms 后进入 0x3800。收到该命令后忽略后续串口写入，不自动保存。CDC 1200 波特率自动跳转保持关闭，EEPROM 布局不变。恢复入口用于有记录的诊断复现，不能称为关机修复。

2026-11-17 USB 交接候选在跳转前增加 USB_INT_EN=0、SIE/FIFO 复位和 USB_DEV_AD=0；仍等待原 100 ms 后进入 0x3800。当时实际枚举尚待验证。

后续结果：用户确认上述版本成功烧录，但 ISP 枚举仍失败。当时的 `isp-tmod-reset.hex` 另外在最终跳转前清零 TMOD，避免 Arduino Timer0 模式残留；仍是待实物验证的诊断候选，能力位/命令不变。0x03 只声明功能，不能识别这几个候选版本。详见 ISP_INCIDENT.md 的时间线和限制。

2.3.0 起保留用户确认有效的 TMOD 清理路径及进入 ISP 前关灯；上述历史候选的“待验证”不代表当前描述。新版本尚未实物验证，应用版本与能力需同时核对。

2.3.1 统一项目品牌为 oneKeyHall；默认 USB 产品/CDC 接口/制造商字符串及两组默认文本为 oneKeyHall，格式/能力不变。历史 2.3.0 的默认产品名为 OneKeyBoard；已保存名称/文本不覆盖。

## HID 报告（V2.4.0 起，当前沿用）

同一 HID 接口 2，端点 0x83，最大包 16 字节，轮询间隔 10 ms。报告协议下第一个字节为 Report ID。

| ID | 类型 | ID 后负载 |
| --- | --- | --- |
| 1 | 键盘 Input | 8 字节：修饰、保留、6 键 |
| 1 | 键盘 Output | 1 字节 LED 状态，EP0 SET_REPORT |
| 2 | 相对鼠标 Input | 4 字节：按钮、相对 X、相对 Y、滚轮；设备模式 X/Y 总为 0 |
| 3 | Consumer Input | 1 字节，bit 0 Volume Increment、bit 1 Volume Decrement；其余常量 0 |
| 4 | Touch Screen Input | 12 字节：Tip、Contact ID、X lo/hi、Y lo/hi、Width lo/hi、Height lo/hi、Pressure、Contact Count |
| 5 | Touch Screen Feature | 最大接触数 1；GET_REPORT Feature 返回 `[5,1]` |

触点抬起仍携带同一 Contact ID、坐标和 Count=1，Tip=0。压力 0–255，XY/宽高 0–32767。触控模式宽高来自面积的整数平方根；位移不变。当前光标模式使用鼠标报告而非触点坐标。boot keyboard 协议只发送无 ID 的 8 字节键盘报告，并停止设备线性输出；返回报告协议后等待顶部就绪。USB 未配置/挂起时不发 HID，端点忙时不覆盖未发送数据。新报告未包含 System Power/Sleep/Wake 用途。

## ROM 身份和行程灯效（V2.5.0 起）

V2.5.0 应用版本 `[1003,2,5,0,1]`，配置 V05 长度仍 137。bit 5 支持命令 6；bit 6 且配置 V05 才允许新灯效。BootLoader BCD 例如 low=0x50/high=2 → 2.50，与应用版本、应用 USB bcdDevice、配置版本无关。

`chip_read_info()` 在应用初始化时只读扫描 0x3800..0x3FEF，识别 WCH ISP USB 描述符、32 字节配置描述符后的 A7 版本记录 `{0,major,minor,patch}`。公开 ROM 2.31/2.40/2.50 样本通过验证；2.31 的 USB bcdDevice 是 1.00，因此不采用它。无法识别时版本为 0，网页显示“未识别”，不会执行 ISP。扫描有边界、签名、VID/PID 和版本十进制位检查，未来 BootLoader 布局不保证可识别。

按 CH552DS1 §6.7 读取 40 位 UID，传输顺序为 0x3FFC、0x3FFD、0x3FFE、0x3FFF、0x3FFA（0x3FFB 保留），与 WCH 工具日志的低字节在前显示顺序一致。网页和 USB 默认名称都将这五个字节顺序编码成 10 个大写十六进制字符，保留前导零。例如 `32 42 D1 BE 00` → `oneKeyHall3242D1BE00`。空名称的自动生成结果不写入 12 字符自定义名称存储区；USB 产品和 CDC 接口使用 42 字节 UTF-16 描述符。自定义名称仍最多 12 BMP 字符，USB serial-string 字段维持既有值。

行程灯效每 10 ms 检查一次，直接采用校准后的 0–100% 相对行程 p，不另做顶部死区重映射，与 KEY1/KEY2/双击/线性工作模式独立。模式 3 亮度 floor(B*p/100)，模式 4 floor(B*(100-p)/100)，模式 5 亮度 B，模式 6 同模式 3；B 为 config[13]。模式 3/4 使用所选 RGB；5/6 使用全饱和色相，色相按两端值线性插值，交换两端可以反转。沿数值方向插值，不自动走最短色环弧。ADC 故障或未校准时新灯效关闭。保存到设备后无需网页；ISP 待跳转阶段仍保持黑灯，且不改保存的灯效。

## 双击反向和计数（V2.6.0 起）

应用 `[1003,2,6,0,1]`，配置 V06 长度仍 137，能力为 255（0xFF）。新增 bit 7 声明：可选线性双击反向、13 项实时状态和线性累计释放计数。V04/V05 迁移为 V06 保留原配置，双击反向默认关闭。V06 保存后不能回刷旧固件保留配置。

config[124] 的低 3 位预设不变，bit 7 保存反向开关，bit 3–6 保留为零；132（预设 4 + 开关）不允许。现有 Flash 地址 114 原样保存此字节，不扩大存储。双击间隔仍使用 config[5]，默认 200 ms，范围 50–1000 ms；两次有效按下的间隔必须严格小于此值。第二次按下时切换临时方向，后续一对双击切回，三连击只切换一次。原预设输出不等待双击判定、不吞掉手势动作。

音量正/反向预设互换，滚轮上/下互换；触控面积/压力对死区外的映射行程执行 100-p，接触起止仍用原始行程，回到顶部仍抬起。仅面积时固定压力，只有压力时固定面积。当前光标鼠标左键预设没有可反向的连续量，不提供该开关。reversed 为状态数组索引 12 的 0/1，表示相对当前已应用预设的临时方向；上电、设置暂停/应用、重新同步或 USB 状态重置后归零，不自动写 Flash。旧 10/12 项状态仍可读取。

所有线性预设都统计有效按下后的正常释放，复用磁轴触发/释放点或 RT 结果。未达到按下阈值的浅行程不计数；设置中和 ADC 故障造成的释放不计数。一次双击在两次释放完成后增加 2 次。计数仍为 16 位，65535 后回到 0，只有显式保存时持久化。网页约 0.5 秒刷新，不会因查看而写 Flash。

网页独立中英文指令表位于相对于站点入口的 `assets/protocol.html`，导航提供链接；页面覆盖所有 999 命令、0–136 配置字节、状态字段、能力位和错误码，只查阅不发送指令。

## V2.6.1 恢复出厂设置

应用版本为 `[1003,2,6,1,1]`，配置 V06 与能力 0xFF 不变。命令 15 会终止已有设置会话并清除旧备份的恢复资格，释放输出，重置累计计数，保存默认参数。重置后未校准，不会自动输出按键或线性动作；需重新两点校准。USB 名称在重新插拔时更新。BootLoader 和芯片 UID 不变。

网页在用户确认后取消待执行的自动应用，成功后回读默认配置；拒绝或通信失败不显示重置成功，也不自动重试。命令 0/13 的设置会话要求保持不变。
